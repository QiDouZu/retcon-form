# 投稿：把你验过的经验，还给这里

> 开源精神不是"我写完你拿"，是**分享爱，回馈爱**。
> 你走我们猜想的经验，也是我们的参考。**这条经验该加进那个实时变更的仓库里。**

---

## 一、怎么投稿（三选一）

### 方式 A：直接开 issue（最省事）

复制 `issue模板.md` 的内容，填完，发成 issue。我放进 `结果/`。

### 方式 B：PR 放一个文件（想留痕迹）

1. fork 本仓库
2. 在 `验证/结果/` 放一个文件（`.md` 照 `_模板.md`，或 `.json` 照下面格式）
3. 提 PR

### 方式 C：投稿到我的邮箱

`2560840425@qq.com`，标题写「猜想验证投稿」。

---

## 二、一个文件 = 一次验证（规矩）

- **一个测试一个文件。** 别把三条塞一个文件——分不开
- **必须写「什么情况下这个结果不成立」**。跟格式一样：你的结论也要写清它的推翻条件
- 署名可留可不留，匿名就写「匿名」
- 文件别带个人隐私

---

## 三、两种格式

### 格式一：`.md`（照 `_模板.md`）

```markdown
# 我验了 C3

- 猜想编号：C3
- 怎么验的：在什么环境、做了什么、跑了多久
- 结论：支持
- 证据：命令输出 / 数据 / "试了 5 次，5 次都是 X"
- 什么情况下这个结果不成立：条件变了会反过来
- 署名：测试者A
```

### 格式二：`.json`

```json
{
  "claim": "C3",
  "verdict": "支持",
  "by": "测试者A",
  "date": "2026-10-25",
  "note": "怎么验的、结果是什么",
  "condition": "什么情况下这个结果不成立"
}
```

`verdict` 写「支持 / 推翻 / 部分」，用别的词会被当成没填。

## 四、投稿之后会发生什么（实时变更）

1. 文件进 `结果/` 目录
2. 跑 `python 验证/汇总.py` → 生成 **`验证/他人经验.md`**，这一页**实时更新**：谁验了、怎么验的、什么情况下不成立
3. 跑 `python 验证/进度条.py` → 对应猜想多一票，进度条变长
4. **被推翻的猜想退休**，不装作还在路上。你的名字（如果留了）会留在「他人经验」里

---

## 五、授权（先说清）

投稿即视为同意：

- 你的投稿以 **CC BY 4.0** 公开，别人可引用，需署你的名（匿名除外）
- 可以随时要求删掉自己的投稿

---

## 六、为什么要这么麻烦

**因为验证本身，也该是可以被推翻的。**

你验一条猜想，你的验证也留了推翻条件——**下一个人就能验你**。这样才能长。
