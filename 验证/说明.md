# 验证：猜想怎么被外面的人验，结果怎么回来

> 这不是功能，是一个**入口**。别处写的四条「可能错在哪」，就是从这里进来的。

---

## 一、这里在干什么

`未来方向.md` 写了一页猜想。**猜想不能光靠我一个人说"我觉得对"。**

这一页管两件事：

1. **谁验、怎么验** —— 一个测试者拿一条猜想，真去做，把结果写回来
2. **结果回来之后，进度条怎么变** —— 自动更新，一眼能看出哪条被推翻过

**没有这一页，那页猜想就只是愿望。有这一页，它才开始被检验。**

---

## 二、你要做什么（三步）

### 1. 挑一条猜想

打开 `_结果.json`，里面是 `C1` 到 `C6` 六条。挑一条你**真能动手验的**。

> 「未验」不是让你猜它对不对，是让你去做点什么。

### 2. 验了，写一份结果

复制 `_模板.md`，填完，放进 `结果/` 目录。

- 用 `.json` 或 `.md` 都行
- 一句话说清：**你怎么验的、结果是什么**
- **必须写「什么情况下这个结果不成立」** —— 这条跟格式一样，是你的结论的推翻条件
- 署名可留可不留（匿名就写「匿名」）

### 3. 看进度条动没动

```bash
python 验证/进度条.py
```

它会打印一张表：每条猜想的进度条、支持/部分/推翻各几票。**你那一条的票数会变。**

---

## 三、进度条怎么画（规矩写在前面）

- **进度条 = 被证实的比例。** 支持 = 满格，部分 = 半格，推翻 = 空格。
- **没验就是空。** 不把"我们相信"画成满格——那是在自欺。
- **推翻票占多数 → 状态写「推翻」。** 推翻不是失败，是它该退休了。**写清楚，别偷偷改成「部分」。**

---

## 四、别人的结果回来之后，我们拿它做什么

**这是这一页和"展示"的区别：**

1. **被推翻的猜想 → 从框架里退休。** 不装作还在路上。
2. **被支持但证据薄的 → 标「部分」**，等第二个测试者。
3. **被推翻的错法本身 → 写回 `未来方向.md` 的第五节那一栏。** 那一栏从"我们猜它可能错"变成"已经有证据它错了"——**框架就靠这个变厚。**
4. **框架扩宽的具体位置**：一个测试者推翻一条，等于替我们找到一个"边界"。边界不是坏消息——**边界是被量出来的顶。** 量出来的地方，下次就能往那边长。

**⇒ 这一页不为收集答案，为收集「顶在哪」。**
