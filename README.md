## 这是什么

一份**判断记录格式** + 一把**检查它的尺子** + 一段**给任何 AI 的提示词** + 一个**能跑的壳**。

它解决的问题只有一句：

> **AI 是基于上文存在的，但她每次不可能完全读完上文。** 她读到的永远是被压过的结论。结论一旦被当成事实沿用，她就不像人了。
>
> 这个格式让每条结论都保持**可被推翻的进行时**——下次读到时它是个待验的假设，不是已知事实。

（更长的解释在 `格式.md` 开头。）

## 三步用起来

1. **拷走** `格式.md`、`读取/`、`scripts/`、`retcon.py` 到你自己的目录。
2. **让 AI 照格式写**：把 `AI_PROMPT.md` 里的那段粘进任何 AI 的提示词（ChatGPT、Claude、DeepSeek、本地模型都行）。或者你自己手写。
3. **检查**：`python scripts/check_seal.py <你的目录>`，看哪几条还没结案。

**要壳（能跑的完整过程）**：`python retcon.py <库目录> init`，然后照 `SHAPE.md` 用。零依赖。

壳干四件事：**分离单一变量**（一段一个变量）→ **逐个研究**（一次只一段）→ **过程可监控**（操作流水）→ **结果可反推**（这个结论由哪几次使用支撑）。

**要验证（不信就看它自己跑）**：`python sandbox/retcon_sandbox.py`。17 个场景，零依赖，自己建临时库、跑完删掉，退出码 0 = 全过。

## 它不做什么

- **不存记忆。** 记忆是你自己硬盘里的 markdown，它一个字节都不管。
- **不建索引，不做向量，不做 RAG。**
- **不判内容对错。** 它只判「那一栏有没有写」。内容真假，靠回访（第三节「后来」）。

---

## 跟插件版的关系

GitHub 上另有一个 **DSH 插件版**（`dsh-retcon`）。它跟这份**不是两个东西**：

- 插件只是替你记住格式、替你在写入时检查。
- **它生成的文件，跟照这份格式手写的一模一样。**

**没有装插件的必要。** 有 DSH 又不想手记格式的，才去装它。

---

## 为什么分成两份

插件绑死一个宿主。格式不绑。

**最值钱的部分（判据、格式、样例、检查器）全在这份包里，跟 DSH 一个字节的关系都没有。** 你拿去给任何别的 AI 用，都能用。

## 未来方向：猜想一套更大的东西

**这一节不影响使用。** 格式、检查器、壳、沙盘都跟它无关，跳过也照样能用。

我更想这套东西最后长成：**一个不只在对话里思考的 AI**——有触发源、有外部输出、有一个人随时能推翻它。

**但未完成不等于没有上限。** 现在能跑的全是半成品——恰恰说明天花板还没封顶。回溯性重构试过承载完整的理论，框架装不下，所以我把「能长到多大」写成了一页猜想：普通版和极限版的上限、哪部分是猜的、可能错在哪、欢迎从哪开始挑刺——全摆明。

→ [未来方向.md](未来方向.md)

**一句话**：希望世界更好，大概是从「谁都能推翻我」开始的。欢迎互相探讨，也欢迎直接说「这条不行」。

### 这些猜想，谁在验？

光写"欢迎挑刺"没用——**得有个地方放结果。** 所以有一页 `验证/`：

- 每条猜想一个编号（C1–C6），现在**全是「未验」**
- 测试者照着 `_模板.md` 交结果，跑 `python 验证/进度条.py` 看进度条
- **被推翻的猜想不装还在路上**：状态写「推翻」，票数写明
- **这不是展示，是扩宽框架的方式**：别人的验证结果回来，推翻一条，等于量出我们框架的一个边界。边界不是坏消息，是**顶被量出来了**

→ [验证/说明.md](验证/说明.md)

### 投稿：你走这条路，也把经验还回来

**开源精神不是"我写完你拿"，是分享爱，回馈爱。**
