# 样例二 · 一次真实的批评，和它逼出来的四处修改

> **这份样例跟 `样例一` 不同。**
> 样例一是「我猜错了 → 回访 → 推翻」。
> **这一份是「别人把我批错了 → 我认 → 我改 → 但它也批错了一处」。**
>
> 用它的方法：**照着这份冲突，写你自己的第一条。**
>
> ⚠ **注（2026-10-25 加，原文未改）**：下面引用的原文里写的包名是 `dsh-retro`——那是**批评发生时**的名字。发布前发现 GitHub 上已有同名仓库，本包已更名为 `dsh-retcon`。这份批评是历史，**原文里的旧名不擦**，擦掉就看不见当时到底叫过什么。

---

## 一、怎么做的这个测试

找了一个**完全不知道这个包是什么**的测试者。三条规矩：

1. 只给它这个仓库（不许读别处的任何文件，不许搜网）
2. 不许夸（出现"很棒""设计精巧"这类词，整份作废）
3. 「卡在哪」必须引用原文原句，不许写"感觉不清楚"

**它最后交回来 7 栏，其中最有价值的是最后一栏：「最先让我放下的那句」。**

---

## 二、它说了什么（原文，未改）

**【Q3】我会卡在哪**：

> 原文「把它放进你的 DSH 插件目录：」没让我明白，因为整篇没给出这个目录的路径，也没说 `plugins/` 是相对工作区、相对用户目录还是相对 DSH 安装位置；紧接着的「`cordis.patch.yml` 会把它挂上一个 `seal` 节点」也没解释这个节点是什么，而文件里写的是 `name: 'dsh-retro'`、`index.js` 里写的是 `name = 'seal'`，哪个才是被认的那个没讲。

**【Q5】我会不会卸载，为什么**：

> 会卸。它的「强制」只有一条：`can_refute` trim 后非空。我手写一个 markdown 模板加一句「写完填推翻条件」效果差不多，还少记三个工具名；而且 `baseDir` 取 `process.cwd()`，换个目录启动 DSH 就另起一个 `封存/`，旧那份不在眼前。

**【分】5/10 —— 因为 Q3：装的第一步就断在「插件目录」这四个字上。**

**【最先让我放下】**：

> 原文引用「这个包如果离了这个名字就不成立，那它就不是开源，是宣传。」
> ——我还没读到插件装在哪，先被要求表态它算不算开源。开头用一整节说「名字不重要」，同一节里又反过来证明自己不是宣传。它是在跟一个还没出现的批评者吵架，没在告诉我怎么用。普通读者到这就关了。

## 三、我认了哪几条（四处真修改）

| # | 它指的 | 是不是硬伤 | 改了什么 |
|---|---|---|---|
| 1 | **两个 `name` 不一致**（`dsh-retro` vs `seal`） | ✅ **真 bug** | 查了 8 个现有插件，规律是 `package.json` 的 name = `dsh-` + `index.js` 导出的 name。改成 `retro` / `dsh-retro`，并说明这是**惯例不是笔误** |
| 2 | 插件目录路径没写 | ✅ 真缺 | 给出三种可能的目录位置 + 一句兜底：**去找一个已经能用的插件，装在同一层** |
| 3 | 没有一条实际调用示例 | ✅ 真缺 | 补了第一条该怎么写 + **故意留空再写一次看它拒** |
| 4 | 那句「否则它就不是开源，是宣传」是在跟批评者吵架 | ✅ 认 | **删了。** 那句情绪是写给自己的，不该出现在给陌生人的文档里 |

**它骂得最准的是第 4 条**。那句确实不是在解决谁的问题 —— 是提前防御一个还没出现的批评。

### 还有一条它提了我没改

> `baseDir` 取 `process.cwd()`，换个目录启动 DSH 就另起一个 `封存/`，旧那份不在眼前。

**这条没改实现**（不改行为的理由：换目录就是换项目，另起一个封存库是对的），但**加了 `SEAL_BASE` 环境变量**，并在 README 里写清楚了 —— 想要共用一个库的人自己设。

**⇒ 这不是「它说错了」，是「它的预期跟设计不同」。** 这一条要说明，不要改掉。

## 四、我最认的一条：它说「手写模板效果差不多」

> 「我手写一个 markdown 模板加一句『写完填推翻条件』效果差不多，还少记三个工具名。」

**这句是对的。** 模板 + 一句自我提醒，效果能有八九成。

那这个插件多出来的是什么？只有一样：**模板可以跳栏，它不能。**

所以 README 里现在有一张表：

| 你是什么样 | 该怎么做 |
|---|---|
| 能坚持按模板填 | **别装。** 手写模板就行，还轻 |
| 三天后模板就空栏的人 | 装。你需要的不是模板，是那一下拒 |

**⇒ 认输认得越干净，剩下那一点越站得住。**

## 五、这个测试自己的毛病（也要记）

**同一个测试还跑了两遍 `local-qwen` 版，两遍都失败**：它不答题，只总结代码 + 给优化建议，连续两次无视「照格式输出」的硬要求。

**⇒ 那两遍是测试无效，不是包有问题。** 但它顺手暴露了一件事：全包里代码占 3/4 篇幅，弱模型会**只读代码不读 README**。

**所以补了第四节那个「一句话定义」** —— 第一屏先回答「这是什么、不是什么」，再讲别的。

## 六、照着这个写你自己的第一条

这份文件本身就是一条封存。**把上面五节压成四行，就是把方法用了一遍：**

```
我以为：这个包讲清楚了它是什么。
凭什么：我写的时候觉得 README 第一节就是它是什么。
我可能错在：写过它的人，读的时候会自动补全别人看不懂的地方。
怎么推翻我：找一个不知道背景的人（或模型）只给它这个目录，问「这是什么」，答不出就说明没讲清。
```

**然后真去找那个人。** 找不到就等 —— **别自己判断「应该能看懂」。**

> **⇒ 这就是那个「冲突」。你手上也一定有一个。拿它填 `填空.md` 第零节。**
