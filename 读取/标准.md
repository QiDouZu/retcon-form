# 标准 · 一条记忆合不合格

> **这是这个包里唯一"统一"的东西。**
>
> 填空（`填空.md`）给的是**问题**，答案每个人不一样。
> 这份给的是**尺子**，对所有人一样 —— 你拿自己的记忆来量，量完自己知道差在哪。
>
> ⚠ **尺子不判内容好坏。** 它只判：**这一条，能不能被推翻。**
> 一个内容错但能被推翻的判断，好过一个内容对但推不翻的结论。

---

## 一、五项，缺一不合格

| # | 项 | 判据（怎么算过） | 怎么算不过 |
|---|---|---|---|
| **1** | 假设位 | 句子里有「我以为 / 我猜 / 初步判断」这类**认领**，不是把话当事实说 | 直接陈述「X 是 Y」，没有"这是我说的" |
| **2** | 证据指针 | 至少一条能**指到别人能去看的地方**：哪句话、哪一帧、哪次对话、哪一行 | 「凭经验」「感觉」「大家都这么说」 |
| **3** | 反例位 | **至少一条**自己的破绽，且**不是**「可能不够全面」这种废条 | 写了等于没写：「仅供参考」「不一定对」 |
| **4** | **推翻条件** | 一件**别人可以执行**的事：取几帧、读哪段、跑什么、问谁 | 「多想想」「再观察」「实践检验」 |
| **5** | 回访位 | 留了「后来」并且**知道什么时候回来填** | 不打算回访 —— 那就不是记忆，是留言 |

### 一项否决

**第 4 项单独一票否决。** 缺 1、2、3 还能算"写得差"；缺 4 就不是记忆 —— **是一条已经硬化的结论。**

## 二、正面样本（中性例子，不是我们的）

```
我以为：这个库的缓存问题是并发写入引起的。
凭什么：日志里 3 次失败都发生在两个进程同时写同一个 key 的那一秒。
我可能错在：(1) 我只看了 3 次失败，样本太少；
            (2) 也可能是磁盘满，只是那几次恰好并发。
怎么推翻我：把并发去掉改成单进程写，跑 100 次同样的负载。
            若还失败，这个判断就塌了。
```

**五项全过。** 注意它**没有一句好话**，全是可查的东西。

## 三、反面样本（同样中性）

```
结论：这个库的性能问题是架构设计缺陷导致的。
```

**五项全不过。** 问题不在它对不对，在于：

- 没有"我以为" → 它已经把自己当事实了
- 没有证据指针 → 谁都核不了
- 没有反例位 → 作者没找过自己的破绽
- **没有推翻条件 → 这是最要命的一条**

**⇒ 这条不是判断，是判决。** 判决不能改，判断能。

## 四、量表（0-5，每过一项 1 分）

| 分 | 含义 | 该怎么办 |
|---|---|---|
| **5** | 合格 | 收下，等回访 |
| **4** | 差一项 | 看差哪项；**差第 4 项 = 0 分** |
| **3** | 半记忆 | 补证据或补反例 |
| **2** | 有想法没材料 | 别存，先去拿材料 |
| **1** | 只有结论 | 这不是记忆 |
| **0** | 话都不是自己的 | — |

**⚠ 自评会偏高。** 找一个人（或一个不知道背景的模型）按五项打，比你自评准 —— **你自评时，第 4 项永远看起来"能推翻"。**

## 五、拿你自己的东西来试（这一步不做，上面全是废话）

### 第一步：找三条你最近写下的判断

从哪里找都行：聊天记录、笔记、朋友圈、心里一直挂着的那个念头。

### 第二步：按五项逐条打

```
第 1 条：________________________
  [ ] 假设位  [ ] 证据指针  [ ] 反例位  [ ] 推翻条件  [ ] 回访位
  得分：__/5   差在哪：____________________

第 2 条：________________________
  [ ] 假设位  [ ] 证据指针  [ ] 反例位  [ ] 推翻条件  [ ] 回访位
  得分：__/5   差在哪：____________________

第 3 条：________________________
  [ ] 假设位  [ ] 证据指针  [ ] 反例位  [ ] 推翻条件  [ ] 回访位
  得分：__/5   差在哪：____________________
```

### 第三步：只改一条

**挑分最低的那条，把第 4 项补上。** 不用改别的。

> **这一条比读完整份标准有用。** 标准看起来懂了不算懂，改出一条才算了。

## 六、这份标准自己的标准

**你也该拿它量我这份标准。**

- **第 1 项**（假设位）：这份标准通篇是祈使句，没写"我以为"—— **但它不是判断，是规范**，规范不需要假设位。
- **第 4 项**（推翻条件）：**它在哪里会错？** → 如果一条记忆内容荒谬但五项齐全，它能拿 5 分。**这是这份标准的已知漏洞，不是疏忽。**
- **为什么留着**：它管的是**格式合格**，不管内容对错。**判定内容对错需要另一套东西 —— 那部分我没有。**

**⇒ 一份不肯说清自己边界的标准，本身就是不合格的判决。**

---

## 七、⚠ 什么时候**才配**用这个（绝大多数时候不配）

**这一节比前面六节加起来重要。**

**回溯性重构不是常态。** 它是**只在关键处、极限处才动的一刀**。平时你不需要它 —— 你只需要记住。

**⇒ 每条记忆都封存 = 每条都没有重点。** 那是把工具用成了负担。

### 极限判定：命中一条才封

| # | 情形 | 为什么是极限 |
|---|---|---|
| **1** | 这个判断**赌注大** —— 错了会连带作废后面一串 | 它下面是承重墙 |
| **2** | 它**反直觉** —— 你自己都不太信，但暂时没别的解释 | 不信的判断最容易被事后改写 |
| **3** | 你**已经在用它了**，但说不清凭什么 | 用了却说不清，是硬化最快的地方 |
| **4** | 有人**跟你说的相反**，而你说不出他对在哪 | 冲突现场，判断最脆 |

### 反例：这些**不该**封

- 日常偏好（「今天想吃面」）—— 明天可能就变了，不值得立假设
- 已确认的事实（「这个函数返回 promise」）—— 有文档可查，拆了就是浪费时间
- 随手的选择（「先试试 A 吧」）—— 试完就完了，没有"后来"
- **情绪**（「我烦」）—— 那是状态，不是判断

**⇒ 命中不了上面四条，就别封。写个笔记就行。**

**⇒ 一个 `封存/` 里有 200 条的人，通常一条都不重要。10 条以内的，才值得看。**

## 八、衍生：一条封存会生下一条

**封存不是孤立条目，是链。** 一条封存被推翻，通常不是结束，是**下面冒出一条新的**。

### 三种衍生

| 类型 | 长什么样 | 例子 |
|---|---|---|
| **① 推翻生** | 「后来」判它塌了 → 塌在哪，就是下一条的假设 | 以为是论证线，实际是清单体 → **新的假设：那 12 个坑之间有共同点吗** |
| **② 裂缝生** | 封存自己写的「可能错在哪」，验的时候有一条真中了 | 「我可能把节标题页当论点页」中了 → **新的假设：我取样时是不是总偏向字多的帧** |
| **③ 边界生** | 这条在 A 成立，在 B 还成立吗 | 「4 帧不许画趋势」→ **新的假设：12 帧呢？多少帧才够画** |

### 规矩

1. **每条新封存在开头写一行**：`> 衍生自：<上一条的文件名> · <推翻/裂缝/边界>`
2. **一条封存最多生三条。** 生出五条说明第一条问得太宽，**该拆的是第一条**。
3. **衍生链超过三层，停下来问一句**：我是在推进，还是在绕？

### 为什么必须有这一层

**没有衍生，封存就是一个坟场**：一条条躺着，谁也不挨着谁。
**有了衍生，它才是重构**：每次推翻都不是白翻，它长出下一次要验的东西。

**⇒ 而他原话那条判据是：「一句话解出多个关键词 → 两个关键词读同一句 = 一次回溯性重构」。**
**衍生的意思一样：一条封存里已经藏着下一条要读的位置，就看你翻不翻。**

### 落法（举例）

```markdown
# 12 个坑之间有共同点吗

> 衍生自：20261025_BV11jnm6bENb_记忆功能.md · 推翻生

## 一、我的假设（原文，写完不改）
### 那是什么
我猜那 12 个坑背后是同一件事：**它们都是「记忆不由你控制」的不同表现**。
...
```

## 九、注释要表明成长性 —— 但成长的是这套东西，不是你

> **先钉死「成长性」这个词指的是谁。**
>
> 标一个人「有成长性」= 考核他。**人会开始写给人看的话。**
> 标一套东西「有成长性」= 它还能不能改。**那是可持续性。**
>
> **这一节用的是后一个。**

### 那一栏问的是：这条之后，你把**标准/规则/工具**改了哪里

**不问「你学到了什么」。问：**

> **「这一条之后，那套东西改了没有？改了哪一条？」**

| 写法 | 指向 |
|---|---|
| 「我进步了，以后会更谨慎」 | ❌ 指向人 → 变成自我评价 → 下一句就是表演 |
| 「**改了第 X 条规则**」 | ✅ 指向物 → 改的是哪一条，你能指出来 |
| 「**什么都没改**」 | ✅ 也合法。至少你知道自己没改 |

**⇒ 成长性 = 这条记录有没有反作用到那套东西上。**

### 为什么必须是「反作用到工具上」

**一个人觉得自己想明白了，是最不可靠的信号。** 你自己就是判官，永远判自己过关。

**但一条规则改没改，是外人能看见的。**

- 规则里多了一句「取帧必含首尾」→ 能查
- 没多 → 也看得见

**⇒ 把「成长」从「我觉得我长进了」挪到「规则里多了一行」，它才不是空的。**

### 三种情况，你自己判断属于哪种

**1. 改了** —— 你能回答吗：**改的是哪一条？为什么是这一条而不是别的？**

**2. 发现刀口不对，但工具没错** —— 你能回答吗：**错在判断，还是错在框架？**

**3. 什么都没改** —— 你知道原因吗：**这次推翻对你下次的操作，到底有没有影响？**

**⚠ 这三种怎么写，我不给例子。**

**因为没有人真的有"写对了"的样子。** 我要是写一个范例，那就是在给你一个结果 —— 而我的那次也是坐下来那一刻的想法，它可能对下一个对象完全无用。

**⇒ 这里给的是问题，不是填空。**

### ⚠ 但这一栏也不许滑成「必须每次都有改动」

**大多数推翻就是推翻，什么也不会留下。**

**写「无」不扣分。** 硬写「这次我学到了要更细心」才是扣分项 —— **那是凑成长性。**

### 自查一句

> 「这条之后，我下次用的那套东西，跟这条之前相比，一模一样吗？」

**一样 → 写「无」。不一样 → 写改了哪一条。**

**⇒ 一套只被人夸、从没被人改的东西，活不久。** 你会去改它，才说明你打算用它很久 —— 这才是那个好奇心的落点。
